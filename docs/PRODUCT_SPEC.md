# Amy Novel 产品规格

## 1. 产品定义

Amy Novel 是一款 Windows Electron 桌面应用，同时提供基于同一前端代码的 Web
运行模式。它面向需要从设定批量生产长篇中文小说的创作者，目标不是一次性返回一段
文本，而是持续管理几十万字小说的规划、生成、审阅、正史与上下文。

核心承诺：

1. 本地优先：作品、API 配置、生成记录默认留在用户设备。
2. 作者可控：AI 生成的是候选稿；只有明确接受的章节进入正史。
3. 可中断批量生成：作者指定章节范围，系统按章执行、保存、暂停和续跑。
4. 长篇一致性：每章使用经过预算的 Context Pack，并在接受后提取事实和角色状态。
5. 模型开放：兼容 Amy-PPT 的多供应商思路，优先支持 OpenAI-compatible、DeepSeek、
   OpenAI、Anthropic、Gemini 和 Ollama。

## 2. 目标用户

- 希望从题材和设定快速生成网文初稿的个人创作者。
- 需要控制章节数量、单章字数、总 Token 与费用的批量创作者。
- 需要持续修改大纲、人物和正文，而不是使用一次性聊天窗口的作者。

## 3. 核心对象

- 小说：作品根对象，包含创作目标、题材、预计字数和默认生成策略。
- 故事圣经：世界、角色、地点、势力、规则、文风、禁忌与作者意图。
- 卷 / 章 / 场景：从宏观情节到正文的三级规划。
- 正史：作者已确认的章节、事实、时间线、角色状态和伏笔状态。
- 候选稿：AI 输出但尚未进入正史的正文或结构化修改。
- 生成批次：指定章节范围的一组可暂停、恢复、重试的任务。
- Context Pack：为单章生成构建的、受 Token 预算约束的上下文快照。

## 4. 核心用户流程

### 4.1 快速创建

1. 输入书名、题材、核心设定、预计总章节、单章目标字数。
2. 选择从空白开始或让 AI 生成故事圣经。
3. AI 生成总纲、分卷方案和章节目录候选。
4. 作者审阅并确认，进入小说工作台。

### 4.2 指定范围批量生成

1. 作者选择起始章、结束章、单章目标字数和生成策略。
2. 系统预估章节数、输出 Token、上下文 Token 与费用。
3. 创建批次；调度器默认串行逐章运行。
4. 每章依次执行：构建上下文、生成草稿、结构校验、连续性检查、保存候选。
5. 根据审批策略：等待作者逐章接受，或自动进入下一章但保持候选状态。
6. 用户可暂停；当前模型请求完成后进入安全暂停点。
7. 恢复时从最后一个未完成章节继续，不重复已成功任务。

### 4.3 接受章节

1. 作者比较当前正文与候选稿。
2. 接受后创建不可变章节版本。
3. 提取章节摘要、事实、时间线、角色状态、关系与伏笔变化。
4. 结构化变化仍以候选形式展示；作者确认后写入正史。
5. 下一章的 Context Pack 才能使用这些正史数据。

## 5. 批量生成规则

- 批次按章节拆为独立 Job；任何 Job 都可重试。
- 同一本小说默认并发数为 1，防止后章使用不到前章新状态。
- 可配置“仅生成候选”“生成后自动连续性审查”“审查通过自动接受”。MVP 只启用前两项。
- 章节任务必须记录 prompt 指纹、模型、参数、用量、错误和上下文快照编号。
- Token 不足或模型限流时进入 `blocked`/`waiting_retry`，不得丢失进度。
- 每次请求前执行预算检查；超过阈值时压缩较低优先级上下文，不能静默截断关键规则。
- 停止分为“暂停批次”和“取消当前请求”；取消不删除已保存结果。

## 6. Context Pack 优先级

必须包含：

1. 作者意图与禁止事项。
2. 当前卷、章、场景规划。
3. 上一章结尾与最近章节摘要。
4. 本章出场角色最新状态。
5. 相关正史事实、时间线、伏笔和世界规则。
6. 文风圣经与输出格式契约。

按需检索：远期章节、参考资料、低相关角色、历史对话。系统必须展示本次上下文来源，
允许作者在生成前排除错误材料。

## 7. MVP 功能范围

### P0

- Windows Electron 与 Web 双宿主。
- 书架、创建小说、归档与回收站。
- 卷/章/场景树与章节状态。
- 章节规划及范围批量生成任务配置。
- 模型配置契约、任务进度、暂停/恢复/重试。
- 正文编辑、自动保存、版本快照。
- 故事圣经、角色、地点、势力、时间线、伏笔。
- 候选稿接受/拒绝与连续性检查。
- TXT、Markdown、DOCX 导入；Markdown、TXT、DOCX 导出。
- Token 与费用记录。

### P1

- SQLite FTS 检索、可选 Embedding、关系图和时间线可视化。
- 封面与人物图生成、TTS、发布前检查。
- 模型任务路由、Prompt/Skill 管理、项目模板。

### 非目标

- 第一阶段不做登录、云同步、社区、推荐、短信、管理后台和多人协同。
- 不承诺“一次点击无人值守生成整本即可发布”；质量控制必须可插入审批点。

## 8. 非功能要求

- 每个已接受章节至少保留一个不可变版本。
- 应用异常退出后，最多损失当前编辑防抖窗口内的内容。
- API Key 不进入业务数据库、日志、导出包和 Prompt 指标。
- 生成器与模型供应商解耦；新供应商不得修改小说领域层。
- 数据库迁移可前进，项目备份可在同一主版本恢复。
- 所有结构化模型输出使用 Zod 校验，失败时可修复或明确报错。
