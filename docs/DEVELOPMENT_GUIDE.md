# 开发与维护规范

## 1. 文档职责

每类信息只保留一个权威来源：

| 信息 | 权威文档 | 更新时机 |
| --- | --- | --- |
| 当前任务、优先级、状态、验收标准 | `BACKLOG.md` | 每次任务开始和结束 |
| 阶段目标与产品方向 | `ROADMAP.md` | 阶段调整时 |
| 已实际执行的验证结果 | `ACCEPTANCE_REPORT.md` | 完成一轮验收后追加 |
| 分层、数据流和技术边界 | `TECHNICAL_ARCHITECTURE.md` | 架构发生变化时 |
| 表、迁移和持久化语义 | `DATABASE_DESIGN.md` | Schema 或迁移变化时 |
| 产品行为与交互 | `PRODUCT_SPEC.md` / `INFORMATION_ARCHITECTURE.md` | 用户行为变化时 |
| AI 接手规则 | 根目录 `AGENTS.md` | 工作方式或门槛变化时 |

设计文档可以描述未来，只有 `BACKLOG.md` 可以声明任务状态，只有验收报告可以声明某次
检查已经执行。旧验收数字作为历史保留，不回写。

## 2. 任务状态与完成定义

- `[ ] 待办`：尚未开始，或只有设计没有可运行实现。
- `[~] 部分完成`：主路径存在，但仍缺验收标准、平台一致性或关键测试。
- `[x] 已完成`：代码、两端适配、必要迁移、测试和文档均满足验收标准。
- `[!] 阻塞`：缺外部授权、付费 API、证书或无法在仓库内解决的条件。

一个任务标记完成前必须同时满足：

1. 真实入口可达，不是孤立函数或只存在于 mock；
2. Electron/Web 的适用范围明确，需双端时两端行为一致；
3. 非平凡规则至少有一个可运行测试；
4. `pnpm check` 通过；涉及构建或平台变化时 `pnpm verify` 通过；
5. `BACKLOG.md` 写明证据，相关设计/数据文档同步；
6. 不新增密钥泄漏、正史绕过或数据不可恢复路径。

## 3. 最小开发流程

1. 从 `BACKLOG.md` 选择一个 ID，先读它引用的证据和验收标准。
2. 用搜索追踪调用链，优先复用既有 Domain/Application 规则。
3. 先修共享根因，再接 Electron/Web；避免在页面、IPC、Web 适配器各写一套规则。
4. 添加最小但能失败的测试；不要为了覆盖率制造无行为价值的测试。
5. 运行验证命令，更新台账；需要人工操作时明确记录“未验证”，不能推测通过。

## 4. 验证矩阵

| 修改范围 | 最低验证 |
| --- | --- |
| 文档、样式、纯文案 | 链接/路径人工检查；相关页面构建 |
| Domain 规则、解析器、状态机 | 对应 Vitest + `pnpm check` |
| PlatformPort、IPC、Preload、Web 适配 | 双端类型检查 + 契约测试 + `pnpm verify` |
| 数据库 Schema/迁移/导入导出 | 新旧库迁移测试 + 数据库测试 + 项目包往返 |
| 生成、预算、重试、正史门禁 | 域测试 + BatchRunner/适配器集成测试 |
| Windows 安装发布 | `pnpm verify` + 隔离 Profile 安装/启动/卸载冒烟 |
| 真实模型行为 | 用户授权后运行 E2E，记录模型、参数、Token 和失败样例 |

命令：

```bash
pnpm check       # TypeScript + Vitest，日常门槛；typecheck 覆盖 src 与 tests
pnpm verify      # check + Web 构建 + Electron 构建
pnpm build:win   # Windows 安装包；仅发布阶段
```

`tsconfig.node.json` 的 typecheck 范围包含 `tests/`：测试文件的导入、fixture 字段与
空值收窄按产品代码同标准检查。新增测试必须通过 typecheck 才算完成，不允许只靠
Vitest 运行时兜底（错误导入只有运行时才暴露，曾造成真实 API 调用浪费）。

## 5. 数据与安全规范

- SQLite 迁移只追加，不重写已发布迁移语义；写入使用显式列名。
- 导出包变更必须兼容旧版本，新增字段提供默认值并做往返测试。
- Web 长篇数据不得继续扩展 `localStorage` 使用；新增大文本或历史版本必须进入 IndexedDB。
- IPC 参数是运行时信任边界，写操作应使用 Zod 或等价解析器校验。
- 日志和 GenerationEvent 只记录摘要、ID、Token、耗时和状态，不记录 API Key、完整 Prompt
  或整章正文。
- 样章可作为用户本地资料保存；生成请求只能注入抽象风格卡，不注入样章原文。

## 6. 代码组织门槛

不为“以后可能需要”创建抽象。出现以下信号时，在当前业务边界内拆分：

- 单文件超过约 800 行且包含多个独立职责；
- 同一规则在 Web/Electron/Renderer 出现两份以上；
- 页面同时承担数据编排、状态机和多个大型视觉区块；
- 新增一个端口需要在五处以上手工保持同构。

优先拆具体模块或组件，不建设通用插件框架。路由页面使用懒加载；大对象存储按领域拆分，
但 Domain 规则保持宿主无关。
