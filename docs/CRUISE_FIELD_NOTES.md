## 二、未根治：主进程 SQLite 写锁挂起（AN-036）

- **症状**（19:4x 与 20:5x 两次）：读全部正常（外部可查库）、**所有写入
  IPC 挂起不返回**（事件/封存/删除一个都写不进）；巡航看门狗解锁重试也
  无效（重试仍撞在挂起的写入上）；持续 ≥30 分钟。
- **恢复**：重启应用（杀 Electron 释放连接）→ 巡航断点自动恢复 → 两次
  均在 2 分钟内完成封存并继续（第二次附带清理 565 条重复伏笔）。
- **候选根因**（待取证）：① libsql 本地连接在某个 batch 事务中途卡死
  （怀疑与多次 HMR 触发的重载并发写有关）；② Windows 文件锁/防病毒扫描
 短暂持有 db 文件；③ WAL/checkpoint 竞态。
- **取证步骤**（下次复现时）：不要立即重启——先 `sqlite3` 只读连接查
  `PRAGMA lock_status`/`sqlite3 .dbinfo`；抓主进程 dump 看挂起的 SQL；
  复查两次复现时间点是否都在 dev HMR 重载后 ~30 分钟。
- **预案**：用户侧"读正常写全停 + 巡航静默"→ 直接重启应用（已验证零损失）。
- **根治已落地（2026-09-02，AN-036 关账）**：
  1. 连接卫生：WAL + busy_timeout=5000 + synchronous NORMAL + foreign_keys
     （`src/main/db/client-guard.ts` applyConnectionPragmas）；
  2. 操作守卫：execute/batch 挂起 >20s 抛可读错误（含"断点续跑、数据
     不丢"指引）而不是永久等待——巡航立即暂停可见，不再静默停摆；
  3. 事件驱动锁自检：超时回调 → BEGIN IMMEDIATE 探测（3s）→ 失败自动
     重开连接并整体重建 repositories；主进程 onRecovery 时间戳留痕；
  4. repositories 排查：全部 batch 为本地语句数组，无跨模型调用长事务。
  复现时的"取证"已自动化（自动重连 + 时间戳日志）；若自动重连后仍持续
  失败，重启应用仍是最终手段（已验证零损失断点续跑）。
