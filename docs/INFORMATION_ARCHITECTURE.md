# 界面信息架构

## 1. 全局导航

沿用 Amy-PPT 的左侧导航、暖色卡片、圆角控件与五套主题。

- 首页：快捷创建、对话创建、导入续写、最近作品。
- 我的作品：书架与作品管理。当前支持带二次确认的永久删除；归档与回收站列为后续能力。
- 生成任务：跨作品查看运行中、暂停、失败和已完成批次。
- 模板：题材模板、故事结构模板、Prompt/Skill 模板。
- 用量：Token、费用、模型和任务维度统计。
- 设置：常规、模型、生成、安全存储、数据与外观。

## 2. 小说工作台

工作台使用可调节三栏结构。

### 左栏：作品导航

- 写作：卷 → 章 → 场景树，显示规划/草稿/候选/已接受状态。
- 故事圣经：创作意图、世界观、文风、禁忌。
- 角色、地点、势力、物品、术语。
- 时间线、关系、伏笔、正史事实。
- 研究资料与导入文件。

### 中栏：主工作区

- 正文模式：编辑器、版本、字数、保存状态。
- 规划模式：总纲、卷纲、章纲和场景节拍。
- 数据模式：角色/地点等结构化编辑器。
- 审阅模式：原文与候选 Diff、连续性问题、接受/拒绝。

### Amy 引导

规划阶段不再常驻独立聊天右栏。Amy 融入当前步骤，只提出当前必须回答的问题、说明本步
所需产物并给出生成与审核入口；正文编辑阶段仍可提供选区操作、Context Pack 来源和
候选稿审阅建议。

## 3. 批量生成向导

分为四步，避免把所有高级参数堆在一页。

1. 范围：选择卷、起始章、结束章；缺失目录时可先生成章纲。
2. 策略：单章字数、生成后审查、失败重试、审批点、模型路由。
3. 预算：预计输入/输出 Token、费用区间和上下文裁剪提示。
4. 确认：展示任务清单，创建批次并进入任务详情。

任务详情包含章节队列、总体进度、当前阶段、实时输出、事件日志、暂停/继续/取消和
失败任务重试。批次状态与章节稿件状态分开，取消批次不会删除候选稿。

## 4. Autopilot 关键节点

规划页使用单任务十步向导，未来步骤默认锁定，作者确认当前结果后才解锁下一步：

1. 创作目标；2. 核心创意；3. 世界观与故事圣经；4. 主角及核心人物；
5. 完整人物体系与名称池；6. 场景和故事实体；7. 故事阶段与分卷；
8. 全部章节标题与章纲；9. 一致性检查；10. 连续正文生成。

前两步发现目标读者、文风、禁忌、卖点、主线矛盾、主角目标或结局方向缺失时，Amy
逐项追问，不能直接跳入生成。第 3–8 步生成后必须进入相应编辑页审核并由作者确认。
分卷和逐章计划由同一次结构规划生成，但分两步审核，防止两次模型调用产生结构漂移。
第 9 步检查故事圣经、人物分层、场景、卷章数量、标题、章纲和分卷归属；未全部通过时
不开放第 10 步。

审核入口必须直接定位目标数据：人物步骤打开角色实体，场景步骤打开地点实体，故事
圣经步骤打开核心文档。作者修改上游数据后，对应步骤及所有下游步骤恢复为待确认状态。

## 5. 路由

```text
/
/novels
/novels/new
/novels/:novelId/write/:chapterId?
/novels/:novelId/plan
/novels/:novelId/bible/:section?
/novels/:novelId/review/:chapterId
/novels/:novelId/generate
/batches
/batches/:batchId
/templates
/usage
/settings/:tab?
```

Electron 使用 HashRouter；部署型 Web 可以切换 BrowserRouter，页面路由不感知数据宿主。

## 6. 章节状态呈现

- `planned`：只有大纲。
- `generating`：模型请求运行中。
- `candidate`：存在待审阅 AI 正文。
- `draft`：作者编辑中的正文。
- `accepted`：已进入正史。
- `needs_review`：连续性或结构检查未通过。

状态必须使用文字和图标共同表达，不能只依赖颜色。
