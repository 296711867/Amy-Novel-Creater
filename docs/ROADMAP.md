# 阶段路线图

## Phase 0：架构基线（当前）

- Electron/Web 双宿主工程。
- 产品、信息架构、技术架构、数据库设计。
- 主题系统与平台端口。
- 书架、创建小说、章节规划、批量生成配置原型。

## Phase 1：本地写作闭环

- [已完成基础] SQLite/Drizzle Schema、数据库门面与启动迁移。
- [已完成章节部分] 章节正文编辑、自动保存和不可变版本快照。
- [已完成基础] 卷章场景完整 CRUD、章节增删与顺序调整。
- [已完成基础] 故事圣经核心文档，以及角色、地点、势力、物品、术语管理。
- [已完成基础] 时间线、伏笔、角色阶段状态及章节关联的动态正史台账。
- [已完成基础] Context Pack 构建器：按优先级组装故事圣经、实体、卷章场景、最近正文与动态正史，支持预算裁剪和不可变快照。
- [已完成基础] Token 用量账本：区分本地估算与供应商实测，预留缓存 Token、费用和模型维度。
- [已完成基础] 模型 Profile、Electron safeStorage 加密密钥、Web 会话密钥与 OpenAI-compatible 连接测试适配器。
- [已完成基础] 单章流式正文生成、候选稿持久化、真实 Token 回写以及接受/拒绝状态机。
- [已完成基础] 可恢复批量生成队列：逐章检查点、串行执行、暂停/恢复、失败重试、退出续跑与章节间 Token 预算门控。
- [已完成基础] Electron 当前请求即时取消、候选稿集中审阅以及批量接受/拒绝。
- [已完成基础] Electron 主进程后台调度器；页面切换不影响生成，进程退出后可按检查点恢复。
- [已完成基础] 候选稿确定性质量检查：字数、场景视角、地点与计划回收伏笔；只生成 Finding，不自动改正史。
- [已完成] Finding 持久化并接入 AI 结构化事实提取，作者确认后再更新正史。
- [已完成基础] Finding 集中审阅 UI，支持逐项解决与忽略。
- [已完成基础] AI 结构化事实提取：严格 JSON 边界、建议持久化、独立 Token 记录，不自动入正史。
- [已完成] 事实建议审阅 UI：逐项接受/拒绝，接受后写入时间线、角色状态或伏笔台账；角色按名称和别名匹配，不自动创建错误正史。
- [已完成] 项目备份与导出恢复：TXT、Markdown、v1 完整项目数据包导出；数据包校验后可作为新作品恢复，重建跨表引用且不覆盖原项目。
- [已完成] Windows 交付基线：Amy Novel 品牌图标、首次启动引导、NSIS 安装配置与发布说明。
- [已完成] 0.1.0 发布验收：打包版启动冒烟、完整测试、诊断报告导出、Apache-2.0 LICENSE 与 NOTICE。
- [已完成] NSIS 独立临时目录安装、隔离 Profile 启动、卸载与清理闭环。

## Phase 2：AI 批量生成闭环

- 复用 Amy-PPT 模型配置思想，实现 OpenAI-compatible 首个适配器。
- Context Pack、章节生成状态机、暂停/恢复、失败重试。
- 候选稿 Diff、接受/拒绝、连续性检查、事实提取。
- Token/费用统计与硬预算。

## Phase 3：增强与生态

- DOCX、EPUB、向量检索、关系图、时间线。
- DeepSeek/Anthropic/Gemini/Ollama 原生适配。
- 封面、人物图、TTS、发布前质量检查。
- Skill/Prompt 包与插件接口。

## 发布门槛

- 任何批量生成任务可在异常退出后恢复。
- 任何 AI 写入可追溯、可拒绝、可通过版本恢复。
- API Key 不出现在数据库、日志和项目备份中。
- [已通过] Windows 安装包通过隔离临时环境安装/启动/卸载冒烟测试；Web 构建通过同一应用契约测试。
