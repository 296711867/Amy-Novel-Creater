## 交接待办（2026-08-30，按优先级）

接手人从这里开始；各项依据见 `E2E_ROLLING_CYCLE.md` 与 `ROLLING_STORY_HARNESS.md` §10。

1. **滚动策划提示词注入封存记忆**（P0，已实证）：第 10→11 章出现衔接矛盾——洛沉璧已消散却在下批再次出场、拆塔钩子被无视。`rolling_structure_planning` 需加入上一周期 expected/actualClosingState 对比、最新人物状态摘要、开放伏笔与时间线尾部（预算受控）。改 `novelPlanningPrompt` 输入即可，不动状态机。
2. **批次记忆审核硬门禁 + 事实提案容错**：封存前检查事实提案处理率与高拒绝率预警；`foreshadow.status` 中文自由文本映射（未回收/open/unresolved→developing 等）、`character_state` 字符串数组容错、`summary` 回退 title；`fact_extraction` 提示词写明字段类型与枚举。实测 55% 提案因形状被拒、伏笔表全空。
3. **一次低温 JSON 修复调用**：规划裸 JSON 失败率约 40%（未转义引号/尾章空字段/截断）。失败时把原始响应+解析错误低温（≤0.2）发回修复一次，不覆盖原运行记录。
4. **实体短引用编号 + 跨阶段近似名合并 + 周期提案去重**：bible/cast 双卡（「灯灵·阿莹」/「阿莹」）、同一反派三种称呼、术语被两周期重复提案。
5. **P3.7 风格（语气）模板库**：见 Phase 2.5 条目——样本提炼为命名风格模板，建书可选套用或 AI 自由发挥；注意“提炼技法、不复刻表达”的合规红线。
6. **Workflow Runner**：以上稳定后启动；无头驱动脚手架已验证全部状态机入口（`tests/e2e/rolling-cycle.e2e.test.ts` 可作 Runner 雏形）。

- [需重构] 旧版一次生成全部章节标题与章纲；改为全书路线骨架 + 当前十章策划包。
- [x] P3.1 十步审核式规划向导：缺失信息逐项追问、当前步骤聚焦、人工确认解锁、一致性门禁后进入正文生成。
- [x] P3.1 人物分层体系：主角/核心配角/酱油人物/跑龙套四级卡片强度，酱油仅章纲提及注入，龙套不进正史。
